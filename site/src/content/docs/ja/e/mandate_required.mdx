**HTTP 403** · `Ludion-Error: mandate_required`

## 何が起きたか

署名は検証できました。しかしこの経路は許しの要る行為（購入、アカウントの変更、予約）であり、*Mandate* を求めています。Mandate は、このサイトで何をしてよいかを書いた、署名付きで短命の委任です。Ludion Protocol v0 では、運営者が Root 鍵で自分のエージェントにかける上限です。動いているエージェントは Session 鍵しか持たないので、自分の上限を広げられません。このリクエストには、ここで使える Mandate が付いていませんでした。

Mandate が付いていても、次のどれかなら、付いていないのと同じに扱います。

- 別のサイトへの Mandate だった。カテゴリへの Mandate なら、このサイトがそのカテゴリに属していなかった。
- 期限が切れていた。
- 取り消されていた。
- `Ludion-Staple` が付いていなかった。Mandate が誰への委任かは、Staple が示す Diver と突き合わせて確かめます。

Mandate には、誰のためか（運営者が出したものは `self`、人が同意したものはサイトごとに異なる仮名）、どこで、何をしてよいか（`read`、`account`、`post`、`reserve`、`checkout`、`delete`）、いくらまで、いつまでが書かれています。氏名、住所、連絡先は入りません。

## サイトがこれを求める理由

正規のエージェントでも、プロンプト注入で操られることがあります。鍵が盗まれることもあります。Mandate があれば、サイトはその行為が本当に許された範囲の内側にあるかを、実行の前に確かめられます。乗っ取られたエージェントも、盗んだ Session 鍵で署名する者も、その外には出られません。

## 直し方

- エージェントの運営者なら、このサイト向けの Mandate を Root 鍵でかけ（Registry はほかの鍵を受け付けません）、コマンドが出す1行で付けてください。

  ```sh
  npx ludion-ai mandate create --site https://shop.example --scope read
  ```

  サイトのオリジンと、この経路が求める範囲を指定します。`--checkout-max`、`--currency`、`--per-day` は決済の上限です。エージェントは Mandate を `Ludion-Mandate` ヘッダーに入れ、署名の対象に含めて送ります。
- Mandate には、いつも Staple を添えてください。`Ludion-Staple` も同じ署名の対象に含めます。
- 期限が切れたり取り消されたりした Mandate は使えません。新しく作ってください。
- v0 の Mandate は運営者自身がかける上限で、エージェントが代理する人の同意ではありません。その同意の画面は、まだ開いていません。
