# （下書き）Mandate の最初の用途は scope: delete（解約・削除の代理）

- 状態：下書き（人間の決定を、Claude が書き起こした。spec の Mandate は §9.5 で凍結中のまま）
- 日付：2026-10-05
- 決めた人：人間
- 関係：spec §11.6（Mandate）、§9.5（凍結）、PRS-2（Mandate v0）、PRS-5（下）

## 決定

Mandate を最初に使うのは、お金ではなく **解約・削除の代理**（`scope: "delete"`）にする。利用者が自分の AI に「このサービスを解約して」「私のデータを消して」と頼み、AI が、利用者の Mandate を持ってサイトの解約・削除の経路に来る。サイトは利用者のパスワードではなく、利用者の Mandate を確かめる。

## 理由

- **お金が動かない。危険が小さい。** 上限、通貨、日ごとの回数（決済の Mandate がいつも抱える難しさ）が要らない。間違って通っても、失うのは「解約の手間」で、利用者のお金ではない。
- **需要がある。** 大規模な情報流出のあと、人は「このサービスから自分を消したい」と思う。何十ものサービスを一つずつ解約する手間は大きく、AI に任せたい仕事の最初に来る。
- **確かめずに受け付けると攻撃になる。** サイトが「AI が言うから」と解約を受け付けると、他人のアカウントを消す攻撃になる。AI が名乗っても（署名があっても）、それは AI の身元であって、利用者がその解約を頼んだ証拠ではない。その証拠が Mandate だ。利用者のパスキーで同意し、名簿が発行し、サイトの `aud` と `delete` の範囲に縛られ、利用者がいつでも取り消せる。
- 仕組みは Mandate v0 にもうある：Gate は `require: { "scope": "delete" }` の経路で、Mandate の無い AI に `403 mandate_required`、範囲の違う Mandate に `403 mandate_scope` を返す（PRS-2、PRS-4、今回の PRS-5）。

## 今しないこと（凍結のまま）

- 同意の画面（ludion.ai でパスキーで同意するページ）は作らない。Mandate はテスト用の発行（ソフトウェアのパスキー）か CLI で用意する。
- 決済の Mandate（`checkout`）は宣伝しない。

## 見直す条件

- サイトが、AI による解約の受け付けを拒むとき（「解約は本人が画面で」を変えない、と事業者が言うとき）。そのときは、解約の手前の「解約の申し出を受け付けた」という記録（受領証）に用途を寄せる。
